# 화면 개편 델타 (기획서 §2 반영)

`Muse_Novel_Studio_기획서.md` §2(전체 여정) 개편을 `구현계획.md`에 대한 델타로 정리한다.
충돌 시 이 문서가 `구현계획.md` §4·§5·§9를 보완한다. 기존 파이프라인(§6·§7·§8)은 그대로 유지한다.

## 1. 워크플로 변경

- 기존 화면 1(작품·설계)을 **아이디어/구조 → 세부 설계** 2단계로 분리한다.
- 탭 구성: 1 아이디어/구조, 2 세부 설계, 3 집필 모니터, 4 작가 검토, 5 엔티티 브라우저.
- 기존 `POST /works/{id}/designs` 평면 생성 API는 유지한다(호환·재현용). UI 기본 흐름은 인계 기반이다.

## 2. DB 델타 (§4 보완)

`works` 확장: `uid`(12자 공개 ID), `stage`(ideas|design|writing), `structure_json`
(`{use_part, use_chapter, total_episodes}`), `ideas_locked`, `updated_at`.
기존 DB는 `_migrate`에서 컬럼 추가 + `uid` 백필한다.

신규 테이블: `idea_threads`, `idea_messages`(role/content/refs/choices),
`story_synopsis`(live) + `synopsis_revisions`(버전 기록), `setting_entries`
(category/title/summary/detail/status), `design_nodes`
(`id` N/P/C/E/S+3자리, design별 kind별 순번).

## 3. API 델타 (§5 보완)

- 작품 키는 정수 id·uid 모두 허용. `POST /works` 제목 필수·80자. `DELETE /works/{key}`
  는 제목 확인 후 영구 삭제하며 `llm_calls`는 유지한다. `GET /works`는 최근 수정 순 +
  `completed_episodes`/`total_episodes`를 포함한다.
- 아이디어: threads/messages(POST는 `idea_chat` 호출 후 user+assistant 저장;
  assistant 메시지에 `proposals{settings[], synopsis_proposal}` 포함;
  `include_synopsis/include_settings/include_messages`로 컨텍스트 명시 선택,
  미지정 시 기존 범위 동작; `@` refs는 설정 제목·노드 ID로 찾아 전문 포함),
  synopsis PUT(버전+리비전; UI는 읽기 전용, 제안 버튼이 호출), settings CRUD
  (생성 시 `status` 지정 가능; 작품별 고유번호 `code` D001~ 자동 부여),
  `POST …/extract`(`idea_extract`, 저장 안 함,
  UI 미사용·호환 유지), `POST …/handoff`(잠금+구조 저장+설계·루트 시드).
  잠금 후 쓰기는 409.
- 설계 트리: nodes CRUD/move/archive/search, `GET /nodes/{id}`(자식 한줄 포함),
  `POST /nodes/{id}/chat`(`design_chat`), `POST /nodes/{id}/expand`(`design_expand`).
  제안은 저장하지 않고 프론트가 일반 쓰기로 적용한다.
- Episode 노드는 `episode_outlines`에 upsert 동기화한다. `advance` 성공 시 작품
  `stage=writing`으로 갱신한다.

## 4. AI 묶음 델타 (§6 보완)

신규 bundle 4종, 모두 `MetaClient.chat_json` 경유: `idea_chat`, `idea_extract`,
`design_chat`, `design_expand`. 프롬프트 `server/app/prompts/`,
스키마 `server/app/schemas/ideas.py`.

## 5. UI 델타 (§9 보완)

정적 서빙 유지. 해시 라우터: `#/` 메인, `#/novels/{uid}/{ideas|design|monitor|review|entities}`.
메인: 검색·단계·EP수·수정일 카드, 제목확인 삭제. 아이디어: 채팅(답변+제안 버튼+
선택지+@언급+포함 체크박스/범위 3모드), 줄거리 읽기 전용, 설정정보(제목줄 세그먼트 스위치),
탭줄 Export(MD 전체), 인계 확인 다이얼로그+AI 마이그레이션. 정리제안 패널·설정추가 양식 제거.
설계: 3열 리사이즈(모바일 탭 전환), 트리+편집+파트너, Expand, 구 개요 마이그레이션,
Episode별 집필 점프. 구 `web/` React·`frontend/js/design.js`는 미사용 잔존물이다.

## 6. AI 로그 델타

- `works.structure_json`이 `{use_part, use_chapter, total_episodes, parts[]}`로
  확장. `GET/PUT /works/{key}/structure`(인계 후 409),
  `GET /works/{key}/handoff/preview`(AI 계획+트리 미리보기, 쓰기 없음),
  `POST /works/{key}/handoff`(미리본 계획 확정 적용, AI 호출 없음).
  채팅 `structure` 제안+`include_structure` 컨텍스트, UI 작품 구조 카드.
- `llm_calls`에 `work_id`, `prompt_system`, `prompt_user`, `output_text` 추가.
  모든 `chat_json` 호출은 `work_id`를 전달한다(기존 DB의 과거 호출은 소설 미표기).
- `GET /works/{key}/ai-log`: 해당 소설의 호출만 최신순 반환. UI는 상단 토큰 칩
  버튼 → 전체 다이얼로그(언제·역할·소요·토큰·입출력, 접기식 상세).

## 7. 알려진 제한

- `episode_jobs`·원고는 회차 번호 전역 키라 작품 삭제 시 고아 행이 남는다.
- 노드 부모 해지(루트 이동)는 미지원. 아이디어 스레드 삭제·개명은 미지원.
