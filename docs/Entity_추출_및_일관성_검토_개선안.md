# StorySpine Entity 추출 및 일관성 검토 개선안

작성일: 2026-11-03 (한국 시간)

**1. 목표와 범위**

작성된 화에서 인물·장소·소품·관계·세계관 규칙·사건을 추출하고, 작가가 승인한 정보를 이후 회차의 일관성 검토에 활용한다. 모든 정보와 판정은 원고의 정확한 버전과 근거 구간으로 추적할 수 있게 한다.

현재 SQLite와 Meta 호출 경로를 유지하면서 저장 신뢰성, 사실 표현, 검토 기능을 순서대로 개선한다. 설계의 기준은 다음과 같다.

- 작품과 작가별로 기억을 분리한다.
- 동일 대상의 ID는 원고 수정과 재추출 이후에도 유지한다.
- 속성·상태·관계·규칙·사건을 구분하고, 변화 경위를 이력으로 보존한다.
- 모든 추출 정보와 판정에 검증 가능한 원문 근거를 연결한다.
- 작가가 승인한 최신 기억과 원고 버전을 기준으로 검토한다.
- 추출·검증 실패와 정상적인 빈 결과를 구분한다.

**2. 데이터 모델**

기존 테이블을 한 번에 교체하기보다 아래 개념에 맞춰 보강하고, 기존 API를 단계적으로 전환한다.

| 개념 | 필수 필드와 규칙 |
|---|---|
| Entity | immutable entity_id, work_id, entity_type, canonical_name. 이름의 유일성은 강제하지 않음 |
| EntityMention/Alias | entity_id 또는 미해결 후보, revision_id, unit_id, 원문 표기와 offset, candidate/confirmed/rejected, 판정 근거 |
| NarrativeUnit | work_id, episode_id, manuscript_revision_id, unit_index, start_offset, end_offset, text_hash. offset 좌표 기준 명시 |
| ExtractionRun | run_id, source_revision_id/hash, base_memory_version, prompt/schema/model version, unit별 처리 상태, pending/saved/superseded/failed |
| Fact | subject_id, kind, predicate, typed value/object_id, operation, qualifiers, source span, narrative_mode, story_time, 출처 유형과 confidence, run_id |
| MemoryVersion | work_id, version, 회차별 활성 run 매핑. 승인된 활성 실행의 사실만 공식 조회에 포함 |
| ContinuityIssue | 현재 원고 revision, 기준 memory_version, 관련 fact/event IDs, 이전·현재·중간 evidence, verdict, severity, workflow status |

Fact의 kind는 최소한 `attribute`, `state`, `relation`, `rule`, `event`를 구별한다. 값은 표준 비교용 값과 원문 표시용 값을 분리한다. 중요한 키에는 허용 타입/값을 두되, 작품별 자유 사실을 버리지 않고 별도의 확장 predicate로 보존한다.

예를 들어 ‘하루 두 번만 마법을 쓸 수 있다’와 ‘오늘 세 번째 마법을 썼다’는 다음처럼 저장한다.

```json
{
  "rule": {
    "subject": "character-id",
    "predicate": "ability.magic.max_uses_per_day",
    "value": 2
  },
  "event": {
    "subject": "character-id",
    "predicate": "ability.magic.use",
    "story_day": "day-12",
    "ordinal_in_day": 3
  }
}
```

실제 저장에는 각각의 원고 revision·인용 구간과 근거를 붙인다. 규칙 변경이나 예외가 명시된 경우에만 규칙의 새 버전을 만든다. 행동 기록으로 제한을 덮어쓰지 않는다.

관계도 문자열 속성만으로 표현하지 않고 subject/predicate/object와 유효 시점을 가진다. ‘서연이 민준을 의심한다’는 방향이 있으며 상호 관계라고 자동 확대하지 않는다. 능력·지식·오해는 누구의 관점에서 성립하는지도 필요하다.

**3. 추출과 근거 검증**

추출 결과는 정규화, 동일 대상 연결, 근거 검증을 거쳐 임시안으로 저장한다. 인물뿐 아니라 장소·소품·조직 등 대상의 유형을 보존하고, 이름·별명·문맥을 함께 확인해 기존 Entity 연결 후보를 만든다. 동명이인이나 불확실한 연결은 작가의 판단 대상으로 남긴다.

| 검증 대상 | 처리 원칙 |
|---|---|
| 속성과 값 | 비교용 표준값과 원문 표현을 함께 보존하고, 타입과 허용값을 검사 |
| 대상의 세부 정보 | 좌우·신체부위·소품 종류처럼 의미 있는 차이를 보존 |
| 한국어 표현 | 짧은 지명·별호·합성어를 처리하고, 언어에 맞는 정규화 기준 사용 |
| 인용 위치 | 정규화 대조 후 실제 원문에서 인용을 복원하고 revision·offset 저장 |
| 근거의 의미 | 인용이 실제 주체·속성·값·부정·시간 조건을 뒷받침하는지 확인 |
| 관계와 사건 | 각 참여자의 역할과 대상 간 연결을 확인하고 근거 구간 저장 |
| 동일 원고 내 순서 | unit_index와 원문 offset 또는 event_order로 사실의 순서를 확정 |
| 처리 상태 | 구간별 성공·성공한 빈 결과·실패를 별도로 기록 |

한 문단에 인물과 장소가 함께 등장하더라도 각 인물의 위치를 개별적으로 확인한다. 부상·소유·관계 변화도 해당 주체와 대상이 원문에서 연결되어 있어야 한다. 추출 신뢰도는 검토를 돕는 참고값으로 사용하며, 근거 검증과 작가 승인을 함께 적용한다.

추출에서 검증에 실패한 항목은 제외 사유와 함께 보류한다. 저장과 분석 완료 경로에는 Entity·원고 구간 참조, 근거 구간, 구간별 처리 완료 상태를 확인하는 무결성 검사를 연결한다.

**4. 시간과 주장 방식**

- 서술 위치: 회차·unit·원문 offset. 독자가 그 사실을 읽는 순서다.
- 이야기 속 시점: fact가 실제 성립하는 날짜·장면·상대 시점이다. 불명확하면 unknown을 허용한다.
- 주장 방식: 직접 서술, 인물 대사, 전언, 추측, 가정, 부정, 꿈, 회상 등을 구분한다.
- 승인 시점: 어떤 원고와 분석 결과를 작가가 공식 기억으로 채택했는지 기록한다.

회상에서 밝혀진 과거 사실은 해당 과거 시점에 연결한다. 거짓말·추측은 그 주장 방식과 주체를 기록한다. 회차 검토에는 해당 시점까지 공개된 정보를 사용한다. 초기에는 위 필드와 명시적 시간 조건부터 적용하고, 범위로만 알 수 있는 시간 구간과 인물별 지식 시점은 후속 확장으로 둔다.

**5. 처리 흐름과 저장 규칙**

```text
검토 제출된 원고 revision 고정
  → 원문 unit 분할
  → 유형·사실·관계·규칙·사건 추출
  → 표기/속성 정규화 및 기존 Entity 연결 후보 생성
  → 인용 위치·주체·내용·시간 검증
  → 새 pending 실행을 성공적으로 완성한 뒤 기존 pending을 대체
  → 작가 검토와 저장
  → 트랜잭션 안에서 활성 기억 버전 전환
  → 관련 과거 사실·원문 검색
  → 규칙 기반 후보 + 자유 사실의 의미 비교
  → 중간 설명·예외·회상 여부 확인
  → 근거를 갖춘 판정 및 작가 결정
  → 최신 저장본과 분석 신선도를 확인한 뒤 발간
```

저장 시 준수할 조건:

1. API와 모든 쿼리를 작품/작가 범위로 제한한다. 회차 식별도 `(work_id, episode_no)` 또는 독립 episode_id로 바꾼다. 현재 전역 episode_no를 유지한 채 entities에만 work_id를 붙이는 부분 수정은 부족하다.
2. 추출은 시작할 때 revision과 base_memory_version을 고정한다. 완료 시 대상 원고·상태·기준 기억이 달라졌으면 활성화하지 않고 재검토 대상으로 둔다.
3. AI 호출과 검증이 끝나기 전에는 기존 pending을 폐기하지 않는다. 동시 재추출 결과가 서로 덮어쓰지 않도록 실행 ID를 검사한다.
4. 활성 run 전환, 이전 run 비활성화, 기억 버전 갱신, 관련 캐시 무효화를 하나의 DB 트랜잭션으로 처리한다. 하위 함수가 중간 commit을 하지 않도록 바꾼다.
5. 엔티티 ID는 재추출 전후 유지한다. 단순 이름 중복을 삭제·병합하기보다 mention/후보의 동일성 판정을 보존한다. 이전 실행의 사실은 이력으로 남기고 공식 조회에서는 활성 run만 사용한다.
6. snapshot은 원본이 아닌 캐시다. work와 memory_version을 키에 포함한다.
7. stale 추출안은 저장을 차단하거나 재검증한다. 적용 0건과 처리 성공을 무조건 같은 의미로 취급하지 않는다. 단, 정상적으로 사실이 없는 원고는 성공한 빈 결과로 허용한다.
8. 더 최신 pending이 있으면 발간 전에 저장하거나 명시적으로 폐기하도록 한다. 과거 저장본을 조용히 선택하지 않는다.
9. 앞 화 변경은 그 사실에 의존한 이후 추출·판정을 낡은 것으로 표시한다. 초기에는 같은 작품의 이후 검토 회차를 넓게 무효화해도 되며, 이후 의존성 단위로 좁힌다.

**6. 일관성 검토 입력과 판정**

현재 원고의 인물·별명·장소·소품을 기준으로 관련 사실을 찾는다. 공통 세계관 규칙은 별도로 포함하고, 관련 관계·사건·변경 이력과 각각의 원문 구간을 가져온다. 현재 추출안은 검토 대상이고, 이전 승인 기억은 비교 근거다. 두 역할을 구분한다. 검색 결과는 후보 시점을 중심으로 구성하고, 범위 확장과 페이지 이동을 지원하며 검색이 완료된 범위를 표시한다.

초기 검사는 다음을 병행한다.

- 확실한 제약 검사: 횟수 제한, 사망/생존, 같은 시점의 배타적 위치, 소유·양도, 관계 종료, 연령·날짜 등.
- 의미 비교: 자유 설정, 성격·동기·지식·세계관 설명의 충돌 후보를 관련 근거와 함께 AI에 비교 요청.
- 추가 조사: 애매한 후보에서만 앞뒤 원문·중간 사건·별명 판정·규칙 예외를 검색. 추출 기록에 없다는 이유만으로 원문에도 설명이 없다고 단정하지 않음.

부상은 치료와 완치를 구별하고 부상 종류·경과 시간·작품 규칙을 함께 확인한다. 위치 변화는 장면 생략과 시간 경과를 고려하며, 시간·거리 제약이나 명시된 사실이 충돌할 때 모순으로 판정한다. 소유·부상·위치뿐 아니라 능력 사용, 금기 위반, 사망 후 행동, 관계, 연령도 검사 범위에 포함한다.

독립적인 상태 두 가지를 둔다.

| 구분 | 예시 값 | 의미 |
|---|---|---|
| 분석 판정 verdict | conflict / explained / uncertain | 모순인지, 설명 가능한지, 근거 부족인지 |
| 작가 처리 workflow status | open / fixed / accepted / dismissed | 수정했는지, 의도적으로 수용했는지, 오탐인지 |

‘서사적으로 설명되는 변화’와 ‘작가가 수정 완료한 이슈’를 별도로 기록한다. 작가가 의도한 설정을 수용했다는 사실과 AI가 정상 변화로 판단했다는 사실도 분리한다.

확정 모순에는 이전 근거·현재 근거와 양쪽 source ID가 필요하다. explained에는 설명 사건의 근거를, uncertain에는 부족한 정보와 검색 범위를 남긴다. 도구가 실패하거나 원고 일부를 분석하지 못한 경우 ‘이상 없음’으로 표시하지 않는다.

초기 구현은 MetaClient를 통한 구조화 판정 1회와 작품 범위가 제한된 Python 조회 함수로 구성한다. 추가 조사가 유효하다는 평가 결과가 있을 때 읽기 전용 도구 호출 루프를 붙이고, 조회량·호출 수·토큰 상한을 적용한다.

**7. 4.작가검토 화면 구성**

| 화면 요소 | 표시와 조작 |
|---|---|
| 추출 기준 표시 | 원고 vN, 추출 시점, 기준 기억 vM, 최신/낡음/실패 |
| Entity 연결 | 신규/기존/별명 후보/동명이인 후보를 표시하고 작가가 확정 |
| 사실 종류 | 인물 속성, 현재 상태, 관계, 규칙, 사건을 구분 |
| 변경 검토 | 이전값·새값·연산·이야기 시점·원문 인용을 펼쳐서 확인 |
| 근거 이동 | 사실·이슈 클릭 시 정확한 원고 버전과 구간으로 이동 |
| 저장 후 표시 | 저장된 사실·사건도 계속 조회; 새 임시안과 차이 표시 |
| 이슈 카드 | 이전 근거 ↔ 현재 근거, 중간 설명, 분석 판정과 작가 처리 상태 |
| 분석 완료 표시 | 오류 수와 별도로 전체/부분 분석·실패 unit·근거 검증 상태 |
| 발간 조건 | 최신 저장본 선택, 미검토 변경·낡은 분석·열린 확정 이슈를 명확히 표시 |

일반 화면에서는 읽기 쉬운 한국어를 사용하고, 내부 predicate와 run ID는 필요한 상세 보기에서만 제공한다.

**8. 적용 순서와 완료 기준**

| 단계 | 구현 범위 | 완료를 판단할 검증 |
|---|---|---|
| 1. 기억 저장 신뢰성 | 작품 범위, 회차 식별, 영속 ID·type, 원자적 교체, pending 보존, stale 차단, 최신안 발간 | 다른 작가 정보 0건 노출; 반복 저장에도 동일 ID; 호출/commit 실패 후 기존 기억 유지; 낡은 결과 저장 차단 |
| 2. 사실과 근거 | 원고 구간, 유형별 Fact, 규칙/행동 분리, 사건·관계의 출처, 인용·의미 검증 | 규칙 위반을 저장해도 원래 규칙 유지; 근거 없는 사실/이슈 차단; 회상과 가정이 현재 상태를 오염시키지 않음 |
| 3. 검토 개선 | 관련 기억 검색, 중간 설명, 복합 후보, 판정/처리 상태 분리, 원고로 이동 | 엔티티 수가 늘어도 관련 대상 검토; 반환·치료·시간 생략을 구분; 같은 화 내부 순서와 장거리 의존성 처리 |
| 4. 평가 후 확장 | 한국어 정답셋, 반복 측정, 비용 비교, 필요한 경우에만 추가 조사 루프·불확실한 시간 구간 처리 | 미사용 작품에서 추출/탐지/판정 수치와 비용 개선 확인; 불확실·누락률 함께 보고 |

권장 모듈 경계는 기존 extraction.py/memory.py/consistency.py를 유지하면서 동일 대상 해석, 사실 검증, 검토용 문맥 구성, 후보 탐지를 별도 함수 또는 모듈로 분리하는 수준이다. 기존 데이터의 작품 매핑은 승인된 원고/episode_job 연결로 가능한 부분부터 복원하고, 여러 작품에 걸치거나 근거가 없는 엔티티는 임의 귀속하지 않고 재추출·작가 확인 대상으로 둔다.

**9. 한국어 평가셋과 검증 방식**

초기 30~50개의 대조 사례를 만든다. 같은 사례의 ‘실제 모순’과 ‘정상 변화’를 짝지어 모델이 변화 자체를 오류로 취급하는지 확인한다.

- 별명/개명/동명이인/같은 이름의 인물과 장소.
- 소품 분실→재등장과 분실→반환→재등장.
- 치료받음과 완치됨, 왼팔과 오른팔, 부상 상태에서 수행 가능한/불가능한 행동.
- 사망 후 현재 행동과 사망 전 회상·꿈·소문·명시적인 부활.
- 하루 횟수 제한과 날짜 변경, 규칙 예외와 실제 규칙 변경.
- 도시 이동과 정상적인 장면 생략, 같은 순간 양립 불가능한 장소.
- 다른 인물의 대사·거짓말·가정과 객관적 사실.
- 앞 화 수정, 같은 원고 재추출, 동시 추출, 저장 실패, 최신 pending을 둔 발간.
- 엔티티가 많은 작품에서 관련 대상이 목록 후반에 있는 사례와 과거 사건의 설명이 멀리 떨어진 사례.
- 추출 실패와 성공한 빈 추출, 처리 일부 누락.

측정은 단계별로 나눈다: Entity 연결의 오병합/분리, Fact 추출 P/R, 인용 구간 정확도, 사실과 근거의 의미 일치, 후보 Recall, 최종 판정 P/R, uncertain 비율, 분석 완료율, 작가가 검토하는 카드 수, 호출·토큰·지연 시간. 후보를 가려서 카드 수만 줄인 것을 품질 개선이라고 판단하지 않는다.

정답과 결과를 매칭할 때는 인물·속성뿐 아니라 원고 revision, 이전·현재 unit/구간, 충돌 유형을 사용한다. 정답을 먼저 확정하고 개발용/보류 작품을 나누며, 같은 조건을 반복 측정한다. 평가 기준 변경과 모델/프롬프트 변경을 한 실험에 섞지 않는다.
