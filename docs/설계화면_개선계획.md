# 세부 설계 화면 개선 계획 (아이디어 화면 개선 이식)

- 작성일: 2026-10-30
- 문서 성격: 아이디어/구조 화면(`frontend/js/ideas.js`)에 적용한 채팅·포함 제어·제안 UX 개선을
  **세부 설계 화면**(`frontend/js/storydesign.js`, 라우트 `#/novels/{uid}/design`, 섹션 `#sdesign`)에
  이식하기 위한 확정 계획.
- 보완 관계: `화면개편_델타.md` §5(UI 델타)를 보완한다. 데이터/파이프라인은 기존 유지가 원칙이며,
  단계별로 필요한 백엔드 델타만 §4에 명시한다.
- 용어: 본 문서의 "소설설계 화면" = "세부 설계 화면" = `storydesign.js`(sdesign). `frontend/js/design.js`는
  미사용 레거시(React `Design.jsx` 이식본)이므로 대상에서 제외한다.

## 0. 배경과 목적

아이디어 화면에서 다음을 개선했다: 채팅 컨텍스트 포함 제어(메시지별·전체 체크박스, 범위 3모드),
타이핑 인디케이터, "처리 중…" 버튼, 선택지(choices) 이어가기, 멀티 스레드, 제안 "모두 반영"·
"✓ 반영됨" 상태, hover 툴팁, 설정정보 표시 모드(한줄/이어서/전체)·행 펼치기.

세부 설계 화면의 **설계 파트너(우측 채팅)**·**제안(proposal-list)**은 이보다 뒤처져 있다.
목표는 두 화면의 상호작용 모델을 통일하여 학습 비용을 낮추고, 설계 단계에서도 컨텍스트를
명시 제어하도록 만드는 것이다. 단, 설계 화면의 데이터 모델(노드 트리 + `body` JSON)은
아이디어 화면(설정/줄거리/구조)과 다르므로 **그대로 복사하지 않고 설계 모델에 맞게 재설계**한다.

## 1. 이식 대상 기능 매핑

| # | 아이디어 기능 | 설계 화면 적용안 | 백엔드 | 단계 |
|---|---|---|---|---|
| ① | 메시지별 포함 체크박스 | 설계 파트너 대화 버블에 포함 체크박스 | 필요 | 2 |
| ② | 포함 범위 세그먼트(전체/직전/없음) | 설계 파트너 대화 범위 세그먼트 | 필요 | 2 |
| ③ | 전체 포함 체크박스(indeterminate) | 파트너 대화 전체 포함 토글 | 필요 | 2 |
| ④ | 타이핑 인디케이터(점3개) | 전송 중 파트너 영역에 표시 | 불필요 | 1 |
| ⑤ | "처리 중…" 버튼 상태 | "전송 중…(취소 불가)"·"설계 중…" 문구 통일 | 불필요 | 1 |
| ⑥ | 선택지(choices) 버튼 | design_chat 응답에 choices 추가 | 필요 | 3 |
| ⑦ | 멀티 스레드 | 노드/작업별 설계 대화 저장·선택 | 필요 | 3 |
| ⑧ | AI 실패 복구 | 파트너 메시지 서버 저장 후 재동기화 | 필요 | 3 |
| ⑨ | `@`멘션 본문 파싱 | 메시지 본문에서 `@코드` 파싱(참조 필드 대체·병행) | 불필요 | 2 |
| ⑩ | "모두 반영" 일괄 적용 | 기존 "전체 적용" 라벨·스타일 통일 | 불필요 | 1 |
| ⑪ | 제안 "✓ 반영됨" 상태 | 적용된 제안을 비활성+체크 표시로 유지 | 불필요 | 1 |
| ⑫ | hover 툴팁 미리보기 | 제안·트리 노드 `body` 요약 툴팁 | 불필요 | 1 |
| ⑬ | 설정정보 포함 선택 UI | 참조(refs)를 인계 설정·엔티티 체크박스 선택으로 | 일부 | 2 |

이미 반영된 것: 구조 트리 표시 모드 세그먼트(한줄/이어서/전체), 검색, 보관함 표시.

## 2. 현재 상태와 격차

- **설계 파트너(우, `#pane-partner`)**: 단순 버블 채팅(`partnerMsgs`는 메모리 전용, 화면 이탈 시 소멸).
  참조는 별도 `참조` 텍스트 입력(쉼표 구분). 포함 제어·범위·스레드·타이핑·툴팁 전무.
  `api.nodeChat(nodeId, content, refs)` — 컨텍스트 선택 파라미터·이전대화·choices 없음.
- **제안(`#proposal-list`)**: "전체 적용 / 하위로 추가 / 이 노드에 적용"은 있으나, 적용 후 상태는
  패널 전체가 "적용됨" 텍스트로 교체될 뿐 개별 "✓ 반영됨" 표시가 없다. 툴팁 없음.
- **중앙 편집(`#pane-editor`)**: `node-body`가 raw JSON textarea.

## 3. 단계별 계획

### Phase 1 — UX 통일 (프런트 전용, 저위험)

범위: ④⑤⑩⑪⑫. 백엔드 변경 없음. `storydesign.js` + `styles.css`만 수정.

- ④ `partnerSend`/`expandFlow` 진행 중 `#partner-messages` 하단에 아이디어와 동일한 타이핑
  인디케이터(`.typing` 점3개) 삽입. 완료 시 제거.
- ⑤ 버튼 문구를 아이디어와 통일: 전송 "처리 중…", Expand "설계 중…". 진행 중 비활성.
- ⑩ `renderProposals`의 "전체 적용" → "모두 반영"으로 라벨·버튼 스타일(`proposals-head`) 통일.
- ⑪ 제안 적용 상태 유지: 마지막 응답의 `proposed_children`/`proposed_patch`를 보관하고,
  이미 추가·적용된 항목은 버튼을 "✓ 반영됨"으로 비활성 표시(아이디어 제안 버튼과 동일 규칙).
  식별은 "같은 노드 아래 동일 kind+title 존재" 기준(아이디어 `findSetting`·`sameContent`와 대응).
- ⑫ hover 툴팁 이식: 아이디어의 `ensureTip`/`moveTip`/`data-tip` 패턴을 공용화하거나 복제하여,
  트리 노드와 제안 카드에 `body` 요약(목표·사건 등)을 미리보기로 표시.

수용 기준: 전송 중 점3개 표시·버튼 비활성, 적용된 제안이 "✓ 반영됨"으로 남음,
노드/제안 hover 시 상세 툴팁 노출. 기존 전송·Expand·적용 흐름 회귀 없음.

### Phase 2 — 설계 파트너 컨텍스트 제어 (프런트+백엔드)

범위: ①②③⑨⑬. `nodeChat`에 컨텍스트 선택을 추가하고, 참조 UX를 체크박스 선택으로 바꾼다.

- 프런트: `#pane-partner`에 (a) 대화 포함 범위 세그먼트(전체/직전/없음, 기본 직전 2개),
  (b) 메시지별·전체 포함 체크박스(아이디어 `includedMessages`·`#setting-all` 패턴 재사용),
  (c) 참조 선택 UI — 인계된 설정/엔티티를 체크박스 목록으로 제시(아이디어 설정정보 영역 축소판).
  ⑨ 메시지 본문의 `@코드`도 함께 파싱해 참조에 합산(`parseMentions` 재사용).
- 백엔드: `POST /nodes/{id}/chat`에 `include_messages`/`include_refs`(또는 `include_settings`)
  파라미터 추가. 단, 설계 파트너 대화가 아직 저장되지 않으므로(③·①의 전제) 이 단계는
  Phase 3의 대화 저장과 함께 진행하거나, 임시로 프런트가 보유한 대화 일부를 `history`로
  전달하는 방식으로 선행 구현한다(결정 필요: §5-1).

수용 기준: 작가가 파트너 질문 전 포함 대화·참조를 명시 선택할 수 있고, 선택이 실제 프롬프트
컨텍스트에 반영된다(`llm_calls`의 `prompt_user`로 확인).

### Phase 3 — 구조 강화 (백엔드 주도)

범위: ⑥⑦⑧. 설계 대화를 영속화한다.

- ⑦⑧ 설계 파트너 대화 저장: `idea_threads`/`idea_messages`에 대응하는 `design_threads`/
  `design_messages`(노드 기준) 신설, 또는 기존 메시지 테이블을 설계 노드까지 확장.
  저장 후 아이디어의 실패 복구 패턴(사용자 메시지 서버 저장 → 재조회) 적용.
- ⑥ `design_chat` 스키마·프롬프트에 `choices` 추가(`ideas_chat` 대응). 프런트는 아이디어
  `#choice-row`와 동일한 "대화 이어가기" 버튼 렌더.

수용 기준: 화면 이탈 후 재진입해도 설계 대화가 유지되고, AI 실패 시 사용자 메시지가 보존되며,
응답에 선택지 버튼이 노출된다.

## 4. 백엔드 델타 요약 (단계별)

- Phase 1: 없음.
- Phase 2: `routes`의 node chat 엔드포인트에 컨텍스트 선택 파라미터 추가(아이디어
  `include_messages`/`include_settings` 로직 참고: `server/app/routes/ideas.py`).
- Phase 3: `design_threads`/`design_messages` 테이블(`db.py` `_migrate`),
  `schemas/ideas.py`의 설계 출력 스키마에 `choices` 추가, `prompts/design_chat.txt` 개정.

## 5. 결정 필요 사항 (리스크)

1. **Phase 2 선행 vs Phase 3 병합**: 포함 제어(①②③)는 대화 저장(⑦)이 있어야 자연스럽다.
   Phase 2를 `history` 임시 전달로 먼저 낼지, Phase 3와 묶어 한 번에 낼지 결정.
2. **참조 모델**: 설계의 참조는 노드 `code`(E001 등)와 인계 설정이 섞여 있다. 체크박스 선택
   대상을 (a) 인계 설정만, (b) 설정+엔티티+형제 노드까지 확장 중 어디로 할지.
3. **node-body 구조화 편집**: 아이디어의 구조화 폼처럼 raw JSON을 폼으로 바꿀지(범위 큼).
   본 계획에는 미포함. 별도 과업으로 검토.
4. **해커톤 범위**: 데모 가치 대비 공수는 Phase 1 > Phase 2 > Phase 3. 시간 제약 시 Phase 1만으로도
   체감 통일 효과가 크다.

## 6. 권장 진행 순서

1. Phase 1 구현·검증(브라우저 재현) → 커밋.
2. §5-1 결정 → Phase 2(백엔드 컨텍스트 선택 + 프런트 포함 UI) → 검증 → 커밋.
3. Phase 3(대화 영속화 + choices) → 검증 → 커밋.

각 단계는 독립 커밋으로 끊어 회귀 추적을 쉽게 한다. 공통 유틸(툴팁·포함 체크박스 렌더)은
`ideas.js`와 중복되므로 `util.js`로의 공용화를 Phase 1~2 사이에 함께 검토한다.
