# Muse Novel Studio

Meta AI 기반 장편 웹소설 자동 창작 플랫폼 종합 기획서

2026년 10월 28일 | Meta Global AI Developer Hackathon | 개인 개발자 트랙

목적: 작가와 AI가 장편 작품의 전체 방향을 공동 설계한 뒤, Meta 모델 기반 에이전트가 집필·검증·교정·기억 관리를 자율 수행하고 작가가 10화 단위로 승인하는 제품을 정의한다. 본 문서는 대화에서 확정한 결정, 설계 제안, 해커톤 범위를 구분한다.

## 1. 프로젝트 비전과 확정 원칙

- 작가는 처음에 키워드와 방향을 제공하고 AI와 충분히 대화하여 작품 콘셉트를 확정한다.
- 본격 집필 전 전체 목표 분량(예: 200화)의 구간별 구성과 회차별 짧은 개요를 작성해 작가 승인을 받는다.
- AI는 승인된 설계도에 따라 기획·집필·설정 검증·서사 검토·문장 교정·품질 평가를 수행한다.
- AI는 10화씩 제작하고 작가의 승인 후 다음 10화를 제작한다. 수정 요청이 있으면 재검증한다.
- 승인 전 설정 및 원고 변경은 임시 상태로 보관한다. 승인 후만 공식 기억으로 확정한다.
- 중대한 세계관·결말 변경은 AI가 독단적으로 확정하지 않고 작가에게 제안한다.

## 2. 사용자의 전체 여정

| 단계 | 입력 및 처리 | 승인 결과 |
|---|---|---|
| 아이디어 탐색 | 키워드 입력, AI와 대화, 콘셉트 후보·장르·톤·주제·결말 논의 | 작품 콘셉트 승인 |
| 장편 설계 | 전체 200화 구간→10화 묶음→회차별 제목·사건·복선·연결 요약 | 전체 서사 설계 승인 |
| 설정 상세화 | 인물·세계관 규칙·타임라인·관계·문체·금지 변경 규칙 정리 | 작품 성경 승인 |
| 자동 제작 | 10화의 회차 설계, 초안 집필, 검증, 교정, 반복 수정 | 10화 묶음 검토 대기 |
| 작가 검토 | 원고 열람, 오류 보고, 변경 이력, 변경 요청 | 승인 또는 수정 요청 |
| 확정 및 반복 | 승인 원고와 기억 커밋, 스타일 피드백 저장 | 다음 10화 제작 |

## 3. 200화 계층형 서사 계획

200화를 한 번에 상세 집필하지 않는다. 먼저 전체 서사의 시작·전환점·결말을 정한 뒤 큰 구간과 10화 묶음, 개별 회차의 요약으로 구체화한다. 예시 구간은 1–40화 도입, 41–80화 성장, 81–120화 위기, 121–160화 대결 준비, 161–200화 결말이다. 실제 분할은 작품 특성에 맞춘다.

- 각 회차 계획 필드: 번호, 가제, 핵심 목표, 주요 사건, 인물 변화, 복선 설치·회수, 직전·다음 회차 연결, 필수/선택 제약.
- 전역 검증: 갈등의 장기 지속성, 사건 중복, 복선 회수, 인물 동기, 결말 인과관계, 전개 속도.
- 승인된 설계도는 버전 관리한다. 실집필이 달라질 경우 영향받는 후속 회차 계획을 추적한다.

## 4. 에이전트 구성과 Meta 활용

| 역할 | 주요 책임 | 권장 Meta 활용 |
|---|---|---|
| AI 편집장 | 작업 오케스트레이션, 품질 게이트, 재시도, 승인 요청 | Muse Spark 추론·도구 호출 |
| 스토리 아키텍트 | 콘셉트 협의, 200화 설계, 회차 목표 설정 | Muse Spark |
| AI 작가 | 설정 및 장면 계획에 따라 원고 생성 | Muse Spark |
| 일관성 검증자 | 인물·규칙·시간·복선 충돌의 출처 기반 탐지 | Muse Spark + DB·검색 도구 |
| 서사 편집자 | 개연성·페이싱·대사·감정선 평가 | Muse Spark |
| 교정자 | 맞춤법·문법·문체·반복 표현 수정 제안 | Muse Spark |
| 기억 관리자 | 임시 기억 추출·연결, 승인 후 정식 반영 | Muse Spark 구조화 출력 + DB |

모델 수를 늘리는 것이 목표는 아니다. 동일한 Muse Spark를 역할별 프롬프트와 도구 계약으로 호출해도 충분하다. Muse Image(삽화)·Muse Voice Transcribe(구술 입력)는 추후 확장. Muse Spark Open(파트너 추론)은 특별상 도전 옵션. Muse Code는 개발 보조 수단이다.

## 5. 회차 자동 제작 상태 머신

PLAN → DRAFT → VERIFY → EDIT → PROOFREAD → QUALITY_GATE → READY_FOR_REVIEW → AUTHOR_APPROVED → COMMIT. 품질 검사 실패 시 구체적 수정 작업을 만들어 DRAFT/EDIT로 되돌리고 재검증한다. 재시도 횟수와 비용·시간 한도를 넘으면 작가에게 미해결 이슈를 제출한다.

- 10화 내부에서는 앞 회차의 임시 설정을 뒤 회차에 참조할 수 있다.
- 작가가 7화 내용을 고치면 영향받는 8~10화를 재검증하고 필요 시 다시 생성한다.
- 작가 승인 전에는 공식 세계관 DB와 확정 원고를 덮어쓰지 않는다.
- 각 호출의 입력, 모델 버전, 출력, 사용 토큰, 판단 근거, 수정 이력을 기록한다.

## 6. 기억과 일관성 검증 설계

| 객체 | 주요 필드 |
|---|---|
| Character | 식별자, 성격, 능력, 상태, 관계, 적용 시점, 출처 |
| Event | 사건, 참가자, 발생 시점, 결과, 선행 조건, 원문 출처 |
| WorldRule | 규칙, 예외, 도입·폐기 시점, 근거 회차 |
| Foreshadowing | 복선, 설치 회차, 예상 회수 시점, 상태, 근거 |
| Chapter | 계획 버전, 원고 버전, 승인 상태, 이슈, 검사 결과 |
| StylePolicy | 시점, 문체, 분량, 작가가 승인한 피드백 |

검증은 구조화된 기억 검색과 원문 조회를 결합한다. AI가 제시한 인용문은 저장된 실제 원문과 기계적으로 대조한다. 설정은 단순 참/거짓이 아니라 유효 시점을 가진다. 예를 들어 8화의 능력 부족과 27화의 각성은 모순이 아닐 수 있다. 불확실한 항목은 오류로 확정하지 않고 검토 필요로 표시한다.

## 7. 작가 검토 화면 요구사항

- 10/200화 진행률과 현재 10화 묶음의 상태 표시.
- 각 회차 원고, 회차별 요약, 오류 탐지 및 자동 수정 내역, 남은 이슈 목록 제공.
- 전체 기획 대비 진행 차이 및 다음 묶음 예고 표시.
- 개별 회차 수정 요청, 변경 전후 비교, 10화 묶음 최종 승인 기능.
- 작가의 문체 피드백은 승인된 스타일 정책으로 저장하며 모델 파인튜닝으로 오해하지 않도록 명시.

## 8. 권장 시스템 구성

| 영역 | 권장안 |
|---|---|
| 웹 UI | Next.js / React |
| API | FastAPI |
| 모델 | Meta Model API Muse Spark |
| 워크플로 | 재개 가능한 DB 기반 상태 머신 |
| 데이터 | PostgreSQL JSONB + 전문 검색, 필요 시 pgvector |
| 비동기 작업 | 작업 큐 또는 안전한 백그라운드 워커 |
| 관측성 | 각 에이전트 결과·토큰·비용·지연·검증 로그 |

모든 AI 결과는 JSON 스키마로 검증하고, 생성된 원고와 제안된 수정은 버전별 저장한다. API 오류·중단 시 재개 가능하게 설계한다. 장기적으로 동시 사용자, 저작권, 접근 통제, 비용 상한 정책을 추가한다.

## 11. 해커톤 규정과 확인 사항

- 공식 배점: Impact 30%, Meta AI 활용 25%, 기술 깊이·실행 20%, Demo 25%.
- Meta Model API 또는 Meta 오픈 웨이트 모델을 실질적으로 사용해야 한다. Meta 독점 기능만 가능한 아이디어일 필요는 없다.
- 해커톤 기간에 새로 구현한 범위를 분명히 밝히고 공개 GitHub 저장소와 3분 데모 영상을 제출한다.
- 단순 RAG 또는 기본 챗봇을 넘는 검증·근거·승인 워크플로를 차별점으로 제시한다.
- Meta 크레딧 $150은 사용자 수령 확인. 파트너 Baseten/Modal/Fireworks 각각 $100은 별도 신청·조건부로, 확정 예산으로 간주하지 않는다.
