도달 과정의 교훈 (프롬프트·입력 설계에 반영됨):

1. 위반 행동은 속성 변경으로 잘 추출되지 않는다. 프롬프트에
   "규칙·제한 관련 행동은 반드시 items로" + 예시를 넣어야 한다.
2. `evidence_quote` 출처를 manuscript로 못 박지 않으면 prev_states 문장을
   인용해 대조 실패(deferred)가 된다.
3. verify 입력의 승인 상태에 속성값만 있으면 반증 인용을 못 만들어
   error 대신 deferred가 된다. 속성별 최신 근거(evidence)를 함께 준다.
4. entity 출력에 `events[]`를 추가했다 (중립적 사건 경위 + 참여자 연결).
   events 테이블을 채우는 유일한 경로. 보류분은 proposal set에 묶어
   승인 시에만 커밋된다.
5. 동일 set 안의 같은 이름 create 후보는 하나의 엔티티로 묶는다
   (분절 방지). 커밋 트랜잭션 안에서만 유효.
