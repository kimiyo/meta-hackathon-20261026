1. 시작하기

서버 하나만 띄우면 됩니다. API와 화면을 같은 주소에서 서빙하므로 별도 웹 서버가 필요 없습니다.

cd server
..\.venv\Scripts\python -m uvicorn app.main:app --port 8000

브라우저에서 http://127.0.0.1:8000/ 을 엽니다. 아래 조건이 필요합니다.

  • .env 파일에 MODEL_API_KEY 입력 (없으면 서버가 부팅을 거부합니다)
  • 상단바에 healthy 표시가 뜨면 정상 연결된 것입니다

메인 · 소설 목록

작품 카드에는 작업 단계, 완성 Episode 수, 최종 수정일이 표시됩니다. 제목 검색과 최근 수정 순 정렬을 지원합니다. 이어 쓰기는 마지막 작업 단계로 이동하고, 삭제는 제목을 동일하게 입력해야 영구 삭제됩니다 (AI 사용 기록은 유지). 각 작품은 고유 주소(#/novels/{uid}/…)를 가지므로 링크로 바로 열 수 있습니다. 처음 실행하면 저자 등록(아이디·필명·비밀번호)이 먼저 나오고, 작품은 등록한 저자에게만 보입니다.

탭 5개

탭하는 일
1. 아이디어AI와 대화하며 소재 발전, 전체 줄거리·설정정보 정리, 뼈대 확정 후 설계로 인계
2. 소설 설계Part·장·화·장면 트리 구체화, 설계 파트너와 협업
3. 집필회차별 진행 상황 확인, 다음 단계로 전진, AI 호출 기록
4. 작가 검토원고 읽기·비교, 검증 결과 확인, 수정 요청, 검토 후 확정
5. 설정인물·장소 등 설정 검색과 변경 이력 조회

3. 기본 사용 흐름

메인에서 소설 선택/만들기 → 아이디어 대화·정리 → 설계로 인계 → 트리 구체화 → 회차 전진 반복 → 검토·확정 → 다음 회차 → …
  1. 메인 화면에서 소설을 고르거나 새 제목으로 만듭니다. 만들면 바로 아이디어 화면으로 들어갑니다. 상단의 ← 작품 목록 버튼으로 언제든 메인으로 돌아올 수 있습니다.
  2. AI와 대화하며 소재를 발전시키고, 답변에 붙는 제안 버튼을 눌러 전체 줄거리와 설정정보를 확정합니다. Part/Chapter 사용 여부와 총 Episode 수를 정합니다.
  3. 아이디어 마무리 → 소설 설계로를 눌러 인계합니다. 인계 후 아이디어는 읽기 전용이 됩니다.
  4. 소설 설계에서 트리를 구체화합니다. 화별 정보가 갖춰지면 바로 집필을 시작할 수 있습니다.
  5. 집필 화면에서 회차의 전진 버튼을 눌러 원고를 생성하고 검증까지 진행합니다.
  6. 작가 검토에서 원고를 읽고, 문제없으면 확정하기를 누릅니다. 고칠 곳이 있으면 수정 요청을 보냅니다.
  7. 다음 회차로 같은 과정을 반복합니다. 설정이 궁금하면 설정 화면에서 확인합니다.

4. 탭 1 — 아이디어

아이디어 대화

  • 자유롭게 입력하거나 AI가 제시한 선택지를 눌러 대화를 이어갑니다. 새 대화를 만들어 주제별로 나눌 수 있습니다. AI는 열린 질문 대신 항상 구체적 선택지를 함께 제시합니다
  • 메시지에 @설정제목·@노드ID를 적으면 해당 자료의 전문이 AI에 함께 전달됩니다
  • 대화를 메시지에 포함에서 메시지 포함 방식을 고릅니다. 전부 포함·전부 포함 않음은 모든 메시지를 한 번에 체크/해제하고, 선택에서는 마지막 대화만 체크된 상태로 시작해 각 메시지 앞의 체크박스로 자유롭게 고릅니다
  • 줄거리·설정 앞의 체크박스로 AI에 보낼 자료를 고릅니다. 체크된 항목은 @언급 없이도 포함됩니다. 기본값은 줄거리만 체크이며, 화면 진입과 AI 응답 시점에 기본값으로 리셋됩니다

AI 답변과 제안 버튼

AI 답변은 작가에게 보내는 메시지와 정리 제안 버튼으로 나뉩니다. 설정 후보 버튼을 누르면 설정정보에 바로 추가되고, 줄거리 변경 버튼을 누르면 전체 줄거리가 바로 바뀝니다. 이미 반영된 제안은 "반영됨"으로 표시됩니다. 같은 제목의 설정이 있지만 내용이 다르면 "'제목' 수정 반영" 버튼이 되어 기존 항목을 고쳐 씁니다. 제안 버튼은 AI를 호출하지 않고 즉시 적용되며, 마우스를 올리면 반영될 내용이 말풍선으로 보입니다. 반면 대화창 아래의 선택지 버튼은 대화를 이어가는 용도로, 누르면 그 내용으로 AI에게 다시 물어봅니다.

전체 줄거리

작품 전체의 이야기 흐름을 보여주기만 합니다. 직접 수정할 수 없으며, AI 답변의 줄거리 변경 반영 버튼으로만 바뀝니다.

작품 구조

줄거리 바로 아래에서 구조 수준(Part 사용·Chapter만·미사용), 총 Episode 수, Part 개수와 각 Part의 개략 요약을 정합니다. Part 사용을 고르면 Chapter가 자동으로 함께 켜집니다. 제목 줄의 작품 구조 버튼을 누르면 카드가 접히며 'Part 사용, 200화' 같은 1줄 요약으로 바뀝니다. 줄거리와 함께 인계 전 반드시 확정해야 하며, AI 대화에 항상 포함됩니다(체크 해제 가능). AI가 제안한 구조는 답변의 구조에 반영 버튼으로 적용하고(버튼에 포함된 항목 요약 표시, 마우스를 올리면 상세 미리보기). Part 목록이 있으면 Part 사용이 자동으로 함께 켜집니다. 인계는 이 카드의 저장된 값을 그대로 사용합니다.

설정정보

  • 인물·세계관·사건·Part 이야기 등을 항목별로 보여줍니다. AI 제안 버튼으로만 채워지며, 직접 추가 양식은 없습니다. 각 항목은 고유번호(D001~) 칩과 분류 칩을 가집니다
  • 제목 줄 오른쪽의 한줄 / 이어서 / 전체 스위치로 표시 방식을 고를 수 있고 선택이 유지됩니다. 한줄은 번호·분류·제목·요약을 1줄로(넘치면 …), 이어서는 전체 내용을 펼침으로, 전체는 편집·삭제 버튼과 함께 보여줍니다
  • 항목별 편집·삭제를 지원합니다(취소 불가, 삭제 시 D번호는 재사용하지 않음). 대화 포함은 항목 앞 체크박스로 지정합니다
  • 탭 줄 오른쪽 끝의 내보내기로 줄거리와 설정정보 전체를 Markdown 파일로 받습니다

설계로 인계

아이디어 마무리 → 소설 설계로만 누르면 됩니다. AI가 인계 계획을 세워 확인 창에 생성될 설계 트리(Part·Chapter·Episode 전체 회차)를 미리보기로 보여주고, 확정하면 그대로 생성됩니다. AI가 채우지 못한 회차는 빈 회차로 표시되며 설계에서 이어서 쓰면 됩니다. 전체 줄거리 전문과 설정정보는 설계 최상위 '작품' 노드에 함께 저장되어 설계 화면에서 볼 수 있습니다. 인계 후 아이디어 화면은 읽기 전용이 됩니다.

5. 탭 2 — 소설 설계

소설 구조 (왼쪽)

  • 작품 → Part → 장 → 화 → 장면의 계층 목록입니다. 각 항목은 트리 안에서 P/C/E/S + 3자리 코드(E001 등)를 가지며, 트리 번호(N001 등)와 합친 전체 코드(N002-E001)가 작품 전체에서 유일합니다
  • 추가·검색·보관을 지원합니다. 인계 때 사용하지 않기로 한 수준(Part/Chapter)은 추가 목록에서 비활성화됩니다
  • 이전 방식으로 만든 설계에는 기존 개요에서 Episode 생성으로 트리를 옮겨올 수 있습니다

설계 편집 (중앙)

선택한 항목의 줄거리·상세(JSON)·하위 줄거리 목록을 확인하고 수정합니다. Episode 항목에서는 이 화 집필하기 → 로 집필 화면으로 바로 이동할 수 있습니다. 전체 설계를 끝내기 전에도 화별 집필을 시작할 수 있습니다.

설계 파트너 (오른쪽)

  • 선택한 항목에 대해 AI와 대화하고 변경 제안을 검토합니다. 제안은 적용해야 반영됩니다
  • 하위 설계(Expand): Chapter를 선택하고 Episode 줄거리를 한꺼번에 설계한 뒤 개별/전체 적용합니다

6. 탭 3 — 집필

설계 ID 불러오기

들어가면 현재 작품의 최신 설계가 자동으로 불러와집니다. 다른 설계를 보려면 설계 ID를 입력하고 불러오기를 누릅니다. 소설 설계의 "이 화 집필하기"로 오면 해당 설계·회차가 자동 선택됩니다.

회차표 읽기

  • 진행(P/D/V/R/A/C): 준비→초안→검토→대기→승인→확정 순서의 핍으로 표시합니다. 각 핍에 마우스를 올리면 단계 이름이 보입니다
  • 상태: 현재 단계. 작가 확인 필요는 작가 개입이 필요해 멈춘 상태입니다
  • 상세: 시도 횟수, 원고 버전, 검증/품질 요약, 실패 사유를 보여줍니다
  • 전진: 다음 단계로 한 걸음 진행합니다 (아래 주의사항 참조)
  • 순서: 집필은 1화부터 순서대로만 시작할 수 있습니다. 앞 회차가 확정되기 전에는 다음 회차의 전진·이 화 집필 시작이 비활성화됩니다

전진이 하는 일

  • 처음 누르면: 원고 초안을 씁니다 (준비 → 초안 작성 중)
  • 다시 누르면: 설정 변경 추출 → 연속성 검증 → 품질 검사를 한 번에 수행합니다 (초안 작성 중 → 검토 중)
  • 또 누르면: 검증 결과를 판정합니다. 문제없으면 작가 검토 대기가 되고, 문제가 있으면 자동으로 고쳐 쓰기 위해 초안으로 돌아갑니다
전진은 되돌릴 수 없습니다. 같은 상태에서 반복하면 재시도 횟수를 소모하고, AI 호출 중에는 취소할 수 없습니다.

AI 호출 기록 · 토큰 예산

최근 20건의 AI 호출(bundle, 회차, 입출력 토큰, 지연, 성공/실패)과 오늘의 토큰 사용량을 보여줍니다. 진행률 막대는 확정된 회차 비율입니다.

7. 탭 4 — 작가 검토

회차 번호를 입력하고 불러오기를 누르면 원고와 검증 결과가 표시됩니다.

원고 본문

  • 버전 선택: 고쳐 쓰기 때마다 v1, v2…로 쌓입니다. 이전 버전도 그대로 볼 수 있습니다
  • 이전 버전과 비교: 체크하면 단어 단위로 달라진 곳을 표시합니다 (삭제 빨강 취소선 / 추가 초록)
  • 원고 1화 분량은 약 3,000~5,000자입니다

수정 요청

고치고 싶은 점을 지시문으로 적고 수정 요청 보내기를 누르면, 원고와 입력은 보존한 채 초안으로 돌아가 다시 씁니다. 작가 검토 대기 상태일 때만 가능합니다.

확정하기

원고가 마음에 들면 확정하기를 누릅니다. 원고와 설정 변경안이 한꺼번에 확정되며 되돌릴 수 없습니다. 작가 검토 대기 상태일 때만 누를 수 있습니다.

검증 카드 읽기

이번 회차에서 바뀐 설정마다 "새 문장 vs 기존 근거" 카드가 표시됩니다.

판정의미
일치 ok기존 설정과 일치
변화 change설명 가능한 변화 (개요의 인물 변화 등과 부합)
충돌 error기존 설정과 충돌 — 수정이 필요합니다
보류 deferred판정 보류. "근거 미확인"이면 충돌 증거로 쓰지 않습니다

별명 · 동명이인 판정

새로 등장한 이름이 기존 인물과 같은지 작가가 직접 정합니다. 연결할 인물 ID를 입력하고 확정(빈칸이면 새 인물로 등록), 또는 기각을 누릅니다.

8. 탭 5 — 설정

인물·장소 등의 설정을 조회합니다. 확정된 변경만 표시되며, 미확정 변경안은 포함되지 않습니다.

  • 검색: 이름·ID로 찾습니다. 클릭하면 오른쪽에 상세와 이력이 표시됩니다
  • 회차 지정 상태: 특정 회차 종료 시점의 설정값을 조회합니다 (예: EP 6까지 확정된 나이)
  • 속성 이력 타임라인: 언제·어떤 근거 문장으로 바뀌었는지 시간순으로 보여줍니다

  • 제안 set / 원고 rev: 검증 대상 설정 변경 묶음과 원고 버전의 관리 번호입니다

10. 주의사항

전진은 취소·되돌리기가 없습니다. 누르기 전에 회차와 설계 ID를 확인하십시오.
  • 확정하기는 되돌릴 수 없습니다. 확정된 설정은 이후 모든 검증의 기준이 됩니다
  • AI 호출 중(원고 생성·검증 등)에는 해당 버튼을 중복 클릭해도 추가로 실행되지 않습니다
  • 데이터는 data/studio.db 파일에 저장됩니다. 삭제하면 모든 작품·원고·설정이 사라지니 주의하십시오

11. 문제 해결

증상확인할 것
서버가 부팅되지 않음.env의 MODEL_API_KEY가 비어 있는지 확인
화면에 빨간 오류 상자상자 안 메시지의 API 경로·상태코드를 확인. 일시적이면 새로고침 후 재시도
작가 확인 필요에서 멈춤상세 화면의 사유 확인 (재시도 상한 / 판정 보류 / 예산 소진)
토큰 예산 초과상단 토큰 칩 확인. 일일 예산은 자정(UTC) 기준으로 집계됩니다
AI 응답이 끝나지 않음대화 범위·총 회차가 클수록 오래 걸립니다. 터미널 오류 확인

서버 터미널에 찍힌 Traceback이 가장 정확한 단서입니다. 문의 시 함께 전달하십시오.
