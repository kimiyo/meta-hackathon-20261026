1. 시작하기

서버 하나만 띄우면 됩니다. API와 화면을 같은 주소에서 서빙하므로 별도 웹 서버가 필요 없습니다.

cd server
..\.venv\Scripts\python -m uvicorn app.main:app --port 8000

브라우저에서 http://127.0.0.1:8000/ 을 엽니다. 아래 조건이 필요합니다.

  • .env 파일에 MODEL_API_KEY 입력 (없으면 서버가 부팅을 거부합니다)
  • 상단바에 healthy 표시가 뜨면 정상 연결된 것입니다

2. 화면 구성

상단바

요소의미
작품 pill현재 소설 제목만 표시. 클릭하면 소설 정보 수정 창
← 작품 목록메인(소설 목록) 화면으로 돌아가기. 첫 화면은 항상 메인입니다
healthy 칩서버·DB 연결 상태와 사용 중인 모델명
토큰 칩오늘 사용한 토큰 / 일일 예산 (잔여량)

탭 4개

탭하는 일
1. 작품 · 설계작품 만들기, 설계도(컨셉·구간·회차 개요) 생성과 승인
2. 집필 모니터회차별 진행 상황 확인, 다음 단계로 전진, LLM 호출 기록
3. 작가 검토원고 읽기·비교, 검증 결과 확인, 수정 요청, 승인+커밋
4. 엔티티 브라우저인물·장소 등 설정(기억) 검색과 변경 이력 조회

3. 기본 사용 흐름

메인에서 소설 선택/만들기 → 설계도 생성 → 설계 승인 → 회차 전진 반복 → 검토·승인+커밋 → 다음 회차 → …
  1. 메인 화면에서 소설을 고르거나 새 제목으로 만듭니다. 만들면 바로 스튜디오로 들어가 글쓰기가 시작됩니다. 상단의 ← 작품 목록 버튼으로 언제든 메인으로 돌아올 수 있습니다.
  2. 설계도를 생성합니다 (키워드, 총 회차, 제약 조건 입력).
  3. 설계도를 읽어보고 설계 승인을 합니다. 승인된 설계가 있어야 집필이 시작됩니다.
  4. 집필 모니터에서 회차의 전진 버튼을 눌러 원고를 생성하고 검증까지 진행합니다.
  5. 작가 검토에서 원고를 읽고, 문제없으면 승인 + 커밋합니다. 고칠 곳이 있으면 수정 요청을 보냅니다.
  6. 다음 회차로 같은 과정을 반복합니다. 설정이 궁금하면 엔티티 브라우저에서 확인합니다.

4. 탭 1 — 작품 · 설계

작품 이름

현재 작품 이름은 상단바에만 표시됩니다. 이름을 클릭하면 소설 정보 수정 창이 뜨고, 지금은 이름만 바꿀 수 있습니다. 다른 작품으로 바꾸려면 상단 ← 작품 목록으로 메인에 갔다 오십시오.

설계도 생성

  • 키워드: 쉼표로 구분 (예: 헌책방, 달빛, 비밀 결사)
  • 총 회차: 1~200 (AI가 10화 단위로 나누어 개요를 만든 뒤 하나로 합칩니다)
  • 제약 조건: 줄바꿈으로 구분 (예: 3인칭 시점 유지, 1화당 분량 등)

생성에는 시간이 걸리며, 진행 중에는 취소할 수 없습니다.

설계도 읽기

  • concept: 장르/톤, 주제, 결말 방향
  • 구간(sections): 10화 단위 줄거리 흐름
  • 회차 개요: 클릭하면 펼침. 목표·사건·인물 변화·복선이 회차별로 정리됩니다

설계 승인

내용이 마음에 들면 설계 승인을 누릅니다. 승인 전에는 마음에 들 때까지 몇 번이든 재생성할 수 있으며, 누를 때마다 버전이 하나씩 올라갑니다 (버튼에 다음 버전이 표시됩니다). 승인된 설계가 있어야 집필 모니터에서 첫 전진이 가능합니다.

5. 탭 2 — 집필 모니터

설계 ID 불러오기

들어가면 첫 작품의 최신 설계가 자동으로 불러와집니다. 다른 설계를 보려면 설계 ID를 입력하고 불러오기를 누릅니다.

회차표 읽기

  • 게이트(P/D/V/R/A/C): PLAN→DRAFT→VERIFY→READY→APPROVED→COMMITTED 진행 단계를 색칠된 뱃지로 표시합니다
  • 상태: 현재 단계. NEEDS_AUTHOR는 작가 개입이 필요해 멈춘 상태입니다
  • 상세: 시도 횟수, 원고 버전, 검증/품질 요약, 실패 사유를 보여줍니다
  • 전진: 다음 단계로 한 걸음 진행합니다 (아래 주의사항 참조)

전진이 하는 일

  • 처음 누르면: 원고 초안을 씁니다 (PLAN → DRAFT)
  • 다시 누르면: 설정 변경 추출 → 연속성 검증 → 품질 검사를 한 번에 수행합니다 (DRAFT → VERIFY)
  • 또 누르면: 검증 결과를 판정합니다. 문제없으면 검토 대기(READY_FOR_REVIEW), 문제가 있으면 자동으로 고쳐 쓰기 위해 DRAFT로 돌아갑니다
전진(advance)은 되돌릴 수 없습니다. 같은 상태에서 반복 호출하면 재시도 횟수를 소모하고, AI 호출 중에는 취소할 수 없습니다.

LLM 호출 기록 · 토큰 예산

최근 20건의 AI 호출(bundle, 회차, 입출력 토큰, 지연, 성공/실패)과 오늘의 토큰 사용량을 보여줍니다. 진행률 막대는 커밋된 회차 비율입니다.

6. 탭 3 — 작가 검토

회차 번호를 입력하고 불러오기를 누르면 원고와 검증 결과가 표시됩니다.

원고 본문

  • 버전 선택: 고쳐 쓰기 때마다 v1, v2…로 쌓입니다. 이전 버전도 그대로 볼 수 있습니다
  • 이전 버전과 비교: 체크하면 단어 단위로 달라진 곳을 표시합니다 (삭제 빨강 취소선 / 추가 초록)
  • 원고 1화 분량은 약 3,000~5,000자입니다

수정 요청

고치고 싶은 점을 지시문으로 적고 수정 요청 보내기를 누르면, 원고와 입력은 보존한 채 DRAFT로 돌아가 다시 씁니다. 검토 대기 상태일 때만 가능합니다.

승인 + 커밋

원고가 마음에 들면 승인 + 커밋을 누릅니다. 원고와 설정 변경안이 원자적으로(한꺼번에, 1회만) 확정됩니다. 검토 대기 상태일 때만 누를 수 있습니다.

검증 카드 읽기

이번 회차에서 바뀐 설정마다 "새 문장 vs 기존 근거" 카드가 표시됩니다.

판정의미
ok기존 설정과 일치
change설명 가능한 변화 (개요의 인물 변화 등과 부합)
error기존 설정과 충돌 — 수정이 필요합니다
deferred판정 보류. "근거 미확인"이면 충돌 증거로 쓰지 않습니다

별명 · 동명이인 판정

새로 등장한 이름이 기존 인물과 같은지 작가가 직접 정합니다. 연결할 인물 ID를 입력하고 확정(빈칸이면 새 인물로 등록), 또는 기각을 누릅니다.

7. 탭 4 — 엔티티 브라우저

인물·장소 등의 "기억(설정)"을 조회합니다. 승인되어 커밋된 변경만 표시되며, 미승인 변경안은 포함되지 않습니다.

  • 검색: 이름·ID로 찾습니다. 클릭하면 오른쪽에 상세와 이력이 표시됩니다
  • 회차 지정 상태: 특정 회차 종료 시점의 설정값을 조회합니다 (예: EP 6까지 확정된 나이)
  • 속성 이력 타임라인: 언제·어떤 근거 문장으로 바뀌었는지 시간순으로 보여줍니다

8. 상태와 용어

상태의미
PLAN아직 집필 전 (개요만 있음)
DRAFT원고 초안 있음, 검증 전
VERIFY추출·검증·품질 검사 완료, 판정 대기
READY_FOR_REVIEW작가 검토 대기 — 검토 탭에서 승인/수정요청
AUTHOR_APPROVED승인됨, 커밋 처리 중 (순간 상태)
COMMITTED확정됨. 원고와 설정이 모두 반영됨
NEEDS_AUTHOR작가 개입 필요 — 자동 진행 중단. 상세의 사유를 확인하십시오
  • 시도(attempt): 실패·반려될 때마다 1씩 증가. 상한(3회)에 닿으면 NEEDS_AUTHOR가 됩니다
  • 토큰 예산: 하루 사용량 상한(기본 100만). 소진되면 진행이 중단되고 해당 회차는 NEEDS_AUTHOR가 됩니다
  • 제안 set / 원고 rev: 검증 대상 설정 변경 묶음과 원고 버전의 관리 번호입니다

9. 주의사항

전진은 취소·되돌리기가 없습니다. 누르기 전에 회차와 설계 ID를 확인하십시오.
  • 첫 전진에는 승인된 설계가 필요합니다. 미승인 설계에서는 design_not_approved 오류가 납니다
  • 승인 + 커밋은 되돌릴 수 없습니다. 커밋된 설정은 이후 모든 검증의 기준이 됩니다
  • AI 호출 중(원고 생성·검증 등)에는 해당 버튼을 중복 클릭해도 추가로 실행되지 않습니다
  • 데이터는 data/studio.db 파일에 저장됩니다. 삭제하면 모든 작품·원고·설정이 사라지니 주의하십시오

10. 문제 해결

증상확인할 것
서버가 부팅되지 않음.env의 MODEL_API_KEY가 비어 있는지 확인
화면에 빨간 오류 상자상자 안 메시지의 API 경로·상태코드를 확인. 일시적이면 새로고침 후 재시도
design_not_approved설계 승인 버튼을 먼저 눌렀는지 확인
NEEDS_AUTHOR에서 멈춤상세 화면의 사유 확인 (재시도 상한 / 판정 보류 / 예산 소진)
토큰 예산 초과상단 토큰 칩 확인. 일일 예산은 자정(UTC) 기준으로 집계됩니다
설계도 생성이 끝나지 않음총 회차가 클수록 오래 걸립니다 (10화씩 순차 생성). 터미널 오류 확인

서버 터미널에 찍힌 Traceback이 가장 정확한 단서입니다. 문의 시 함께 전달하십시오.
